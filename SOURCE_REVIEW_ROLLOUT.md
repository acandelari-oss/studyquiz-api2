# Document source review — opt-in rollout

Default: disabled. No migration has been applied by this implementation.

## Enable only after review

1. Review/apply `migrations/20261101_document_source_review.sql` in the intended database.
   It adds only nullable `documents.source_review JSONB` and an object-type check;
   no backfill, topic changes, or source text changes.
2. Deploy backend and frontend together. Set `DOUNO_SOURCE_REVIEW=1` and restart
   the backend. This does not queue or regenerate existing documents.
3. For an explicitly requested retry, valid candidates publish normally while
   unsupported proposals remain inspection-only records. Every eligible teaching
   chunk is accounted for as linked or pending; nothing is automatically declared
   outline-only. Existing chunk roles and text are untouched.
4. Students may confirm an existing same-document topic link (verified chapter
   restrictions enforced), or explicitly mark an entire item as outline/context
   with an explanation. Mixed, unreadable or unrelated content stays pending.
   No new topic or content is generated by review actions.

API: authenticated document-scoped GET `/source-review`, PATCH
`/source-review/{chunk_id}` under `/projects/{project_id}/documents/{document_id}`.
PATCH requires the current revision and unchanged source snapshot; processing
and Study Mode locks apply. Review records commit in the taxonomy publication
transaction. No separate commit, new AI stage, or study-engine changes.

Source text is fetched from chunks, not copied into JSON. Unsupported proposal
text is retained for inspection only. Pending material may not be represented
in topic-based study activities; the UI explicitly warns about this. RAG and
other direct source consumers are unchanged. Zero supported topics still fails
rather than advertising an empty study taxonomy as ready.

## Roll back safely

- Set `DOUNO_SOURCE_REVIEW=0` and restart to restore strict publication for new
  processing. Keep the additive column, GET/PATCH endpoints and review UI for
  any records already published. Disabling the flag does not undo prior student
  decisions, remove valid topics, or erase review records.
- Do not drop the column until outstanding records have been resolved or
  exported. Dropping it would erase source accounting/review decisions.
- There are many pre-existing uncommitted changes in these repositories. Do not
  use `git reset --hard`. Pre-edit copies of changed existing files are at
  `/tmp/douno-source-review-before/` for comparison only, not blind restoration.
- Existing projects were not modified. The source-review feature has not been
  exercised against a production upload/database.

## Validation

Offline SQLite publication/API tests cover complete accounting, deferred
candidates, rollback, stale revisions/source snapshots, ownership, document and
chapter isolation, explicit outline confirmation, Study Mode and deletion.
PostgreSQL JSONB writes use an explicit cast; migration execution and live
PostgreSQL integration are still to be verified in staging.
Frontend mocked tests cover English/Italian display, counts, reassignment,
errors and locks. Full TypeScript baseline: 178 existing diagnostics before
and after, with zero new diagnostics.
